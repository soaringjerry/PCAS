## 三、修复 #238 的范围

2026-10-06 02:47 UTC 上线（主干 b63d65d）。

- 页面读取：名单每次查询只算一次。最慢的一条查询 12.8 秒 → 0.29 秒，新旧查询在线上的输出逐行一致。
- 迁移 041：一条记忆变动时，直接按编号查它属于哪些卡，不再按卡片数重算名单。在恢复库里对全部 5,253 条记忆核对，新旧结果一致（12,478 行，双向无差异）；收起一条记忆（标成被替代或合并） 896 毫秒 → 11 毫秒。
- 第一版修法（把视图里的子查询改成内联）让并发验收失败，CI 拦下，没有上线；已换成上面的做法。
- 新函数 `status_claim_keys` 复制了名单视图的规则，两处要一起改；目前没有自动测试保证两者一致。

#238 不解决 D1–D12，也不解决 B4–B7、B10、B12–B15。第五节的 D13–D42、B16 都是 #238 之后查出的。

上线后要留意的一点：比对恢复后，每收起一条记忆（标成被替代或合并）都会让它所在的卡片过期重建（D6）。上线 6 分钟后已有 64 张卡在排队重建。

## 四、待定的方向

讨论中倾向的做法，尚未批准：

1. 去掉现状卡的建立和重建，「关于你」并入资料库；人、项目、主题作为资料库的筛选条件。
2. 保留期限表。遗忘曲线只往回看，早先说过一次的截止日会沉底，而它越临近越重要。
3. 保留交接说明，改为读「活跃度排在前面的记忆、期限表、长期有效的规矩」来写，规矩不按时间截断，更新用增量方式。
4. 动手之前，用 26 道已审过的私有题对比「有卡片」和「无卡片、只靠活跃度排序」两种情况下秘书的回答，同时确认线上遗忘曲线的排序确实可用。

这会改动白皮书 5.6–5.8 和记忆架构文档。

## 六、建议的处理思路（协调者的建议，未批准）

### 这些问题的共同来源

D1–D42 大多落在六种做法上，改的时候按做法改，不要逐条打补丁：

| 做法 | 例子 | 应该换成 |
|---|---|---|
| 没有依据的上限，超出的悄悄丢掉 | 300、200、60、25、12、15、30 条（D5、D12、D16、D37、D38） | 每个上限写明依据和超出部分的去向；丢了多少要记数、能在观测台看到 |
| 失败后写空，或标成已处理 | D19、D35 | 失败不覆盖已有的好结果；失败计数并告警（B5、D28） |
| 一处变动，整份作废重做 | D6、D7、D18、D20、D26 | 增量更新；过期的照常用，后台慢慢补 |
| 用字面匹配代替判断 | D13、D16、D22、D24、D39 | 交给模型判断，程序只做合理性校验；拿不准的留下并标明，不丢 |
| 派生的东西没有自己的来源 | 期限靠建卡顺带抽、要求靠卡片挑（D15、D16） | 每样东西直接从记忆产生，不经过别的派生物 |
| 验收只看「有没有」，数据又小又只有中文 | D10、D11，英文名字和日期的问题（D13、D22） | 按线上规模（五千条、三百个分组）验收，看内容分布，测试数据中英混合 |

其中 300 条、200 条、12 条、过期截止不留、领域不能新增、四个升档词，都是契约里写的（R3-2、R2-2、R4-4、R3-3、第 1 批 R3、R4-10），不是执行者自己定的。

### 建议的顺序

**第一步：先止损。不涉及方向，可以马上做。**

1. 交接说明过期时照常给秘书，不整段丢掉（D17）。
2. 失败不再写空卡、空交接说明（D19）。
3. 修 B16：找「下一对名字」不放在限时 2 秒的事务里；修好之前先停掉别名确认的排班，免得每分钟报错。
4. 后台失败和排班失败都记原因、计次数（B5、D28）；花费记录补上 token 数（D23）。
5. 现状卡的自动重建先停，已有的卡照常读。它现在每小时最多用 120 次调用，产出的东西第四节已经倾向于去掉。
6. 新旧比较继续跑之前，先人工抽查已有的 94 条退出记录判得对不对（B2 里没做的那一步）。

**第二步：定方向。同意第四节的第 1 条，但第 2、3 条要改写。**

1. 去掉现状卡，「关于你」并入资料库。理由除了 D1–D4，还有 D5、D6、D18–D20 这一串成本和故障都出在「模型整卡重建」上。
2. 期限表保留，但要有自己的来源：记忆写入时就由模型抽成有类型的数据，程序只校验「能解析、不早于说话时间」，不再要求和正则算的相等；过期的留着并标「已过期，不知是否完成」；没说清的留下并注明。第四节第 1、2 条照现在的实现是冲突的（D15）。
3. 「对助手的要求」不经过卡片：全部有效的要求先在自己这一组里整组去重（要先解决 D12），不限范围的每轮都带，限范围的在「要求」内部单独排名取前几条，不和别的记忆抢名额，也不靠字面匹配。
4. 交接说明保留，输入改成「身份、目标、口味里重复说过和最近说的」加全部要求加期限表；过期照常用，按固定节奏重写，不再等全部卡片不过期。
5. 第四节第 3 条里的「活跃度排在前面的记忆」先不要依赖：线上的活跃度现在就是说的时间（D29）。要用它，得先让「用户提及」「回答被采纳」这些信号真的记下来。
6. 领域按用户决定 5 允许新增，或者不再给领域建大分组（D30）。

**第三步：量一次再动手。**

第四节第 4 条的 26 道私有题对比仍然要做，但含义变了：线上「有卡」这一边现在交接说明是空的、要求每轮只带 2 条、期限表只有 7 行，所以它量出来的是「现在这个坏掉的实现」的基线，不能当成对「现状卡这个想法」的判决。建议跑两边：现在的线上，和「不带现状层、只靠检索」（契约 R4-5 的退回路径）。结果作为之后每一步改动的前后对照。

**第四步：把第一张表里「应该换成」那一列写进任务流程规则**，以后的契约和验收照着查：上限要有依据和去向；失败不覆盖；每个后台阶段写明调用预算；验收用线上规模和中英混合的数据。
