# 任务 V：回忆评测集和三种做法的对比

执行者 6.1 Sol，**不能是做任何实现任务的执行者**。分支 `phase2/b4-V-eval`，从 `origin/main` 建（不用等 S0，评测集可以先写）；工作区 `/root/PCAS-wt/b4-V`；Draft PR 的 base 是 `phase2/batch4`（协调者建好后告诉你）。

先读 [并行方案与数据约定](../parallel.md)、[第 4 批契约](README.md) 的 R16–R19，以及三批契约各自的第 1 节（知道产品要做到什么）。你的工作决定了以后怎么判断「回忆准不准」，所以评测集的预期必须从资料本身标出来，不能看着实现的输出反推。

## 要交付什么

### 1 评测集（R16）

`testdata/phase2/eval/`，全部合成数据，一个虚构的人，不要用任何真实的人和线上内容。

- 大约 12 个场景，每个 6–12 份资料、2–3 个问法，再加一批不相干的资料当噪声。资料要像真的：对秘书说的短句、速记、导入的旧聊天（有用户说的也有 AI 说的）、一两份长文件。很多份标题相同。
- 干扰项按契约 R16 列的八种，每种至少两个场景用到。
- 每份资料带「标准抽取结果」：按第 2 批契约 R1 的形状，一个理想的抽取应该给出什么（人、地点、说的是哪天的事、性质）。说话时间用相对「评测基准日」的偏移写，装载时换算，这样评测集不会过期。
- 每个问法标注：标准证据（哪些资料或记忆必须交到模型手里）、干扰项（哪些不该排在标准证据前面）、标准事实（正确答案里必须出现的词，带别名）。
- 一份说明文件：每个场景想考什么、标注的依据。

### 2 检索评测（R17）

`internal/postgres/phase2_eval_test.go`：把评测集按数据约定装进测试库（结构化数据用「标准抽取结果」直接写），每个问法走真实的秘书入口，假模型抓收到的内容，算出召回率和干扰率，打印一张逐问法的表。召回率低于评测集里记录的基线时测试失败。

基线文件第一次留空（或写 0），PR 里报告你量到的数字，由协调者定线。

第 3 批合入之前，这个测试量的是「只有原话直达」的水平；第 3 批合入之后数字应该上升。两个数字都报告。

### 3 对比工具（R18、R19）

`cmd/pcas-eval`：按契约 R18、R19。

- 三种做法只在这个工具里实现，不进产品代码。
- 只连通过参数给的临时库；启动时检查库是不是空的或专用的，不是就拒绝运行，避免有人拿它连线上库。
- 模型通道由环境变量给。你用假模型把整个流程跑通；真实模型由协调者跑。
- 输出一份 Markdown 表格和一份 JSON：每种做法的事实命中率、输入 token、花费、耗时；抽取评测的人、地点、时间、性质各自的准确率。

## 你独占的文件

`testdata/phase2/eval/`、`internal/postgres/phase2_eval_test.go`、`cmd/pcas-eval/`、`docs/evaluations/<日期>-phase2-eval.md`（方法说明和假模型下的结果；真实模型的结果由协调者补）。

不改产品代码。需要产品提供某个入口才能评测时，告诉协调者。
