# 任务 U1：资料库按分组翻记忆（界面）

执行者 Opus 5.5。分支 `phase2_5/b1-U1-frontend`，从合入 O1a 之后的 `origin/phase2_5/batch1` 建；工作区 `/root/PCAS-wt/p25-U1`；Draft PR 的 base 是 `phase2_5/batch1`。

先读 [第 1 批契约](README.md) 的 2.3、2.4 和 R17–R19，以及 [界面与交互原则](../../../design/principles.md)。

## 要交付什么

资料库的记忆列表现在可以按人、按地点翻。加上按分组翻：

1. **分组入口**（R17）：项目、主题、领域各一组，每个分组显示名字和条数，数据来自 `GET /v1/workspace/memory-facets` 的 `groups`。点一个分组，列表只显示它下面的记忆（请求带 `group=<实体 ID>`）。再点一次取消。和已有的按人、按地点、搜索可以同时生效。分组很多时默认每组显示条数最多的若干个，其余收起。
2. **记忆卡片**：显示这条记忆的分组（`groups`），点分组名等于按它筛选。类型用中文叫法显示成一个小标签（身份、口味、对助手的要求、目标、进展、一次性的事、看法、关于别人）；`unknown` 不显示（R19）。`durable` 这一批不显示。
3. **整理进度**（R18）：工作台快照里 `organize.done < organize.total` 时，在列表上方显示一行「已整理 N / M」；相等时不显示。
4. 一个分组都没有时（还没开始整理），不显示分组入口，页面和现在一样。

## 不要做的

- 不出现「规则版本」「落后」「批」「实体」这些词。
- 不做类型的筛选控件，不做分组的重命名、合并、删除。
- 不改按人、按地点翻的现有行为。

## 测试

- 用模拟数据的浏览器测试：有分组时的筛选和取消、和按人筛选叠加、卡片上的分组和类型、进度行出现和消失、没有分组时页面不变。
- 手机宽度下分组入口不撑破页面。
- 文案和测试数据全部虚构。

交付时附电脑和手机宽度的截图各一张（虚构数据）。
