日期：2026-10-01。唯一范围/工作包依据为 [readiness.md](readiness.md)；产品候选复核基线 `7aae834d34b3749bdceaf0a2b704b79e837a391e`。本文件只定义可执行验收，不表示 fixture 已建、阈值已达标或二阶段已开工。第一阶段正式入口仍由 [稳定化](../stabilization/README.md) 裁定；没有修改正式契约。[M1 最新审计](https://github.com/soaringjerry/PCAS/blob/7e4895a31a912cf66916136f6af26ad34350cb91/docs/evaluations/2026-10-01-phase2-context-audit.md)（最终证据提交 `7e4895a31a912cf66916136f6af26ad34350cb91`）的 opt-in 假模型观察用于证实候选装配缺口：观察模式退出0只采证，未来原文要求真实退出1；不能代替真实模型/用户验收。其同conversationId补验仅证实现有confirmed claim依赖的纠正/连来源删除后，历史回复占位且下一轮不重供旧marker；原文typed包、状态/关系链仍须本设计独立验收。

## 1 验收边界与运行入口

主验收走公开 `DeskTurn` 和 `Execute(requestRun)`；自动副手继续走 `RunAgents` 至 provider 最终请求，manual 读取真实交接包。Recall/Expand 只作诊断对照，不允许测试拿 `Recall.Summary` 自行拼 prompt 替代这些入口。测试的 provider 可以固定假模型捕获真实请求；正对照证明捕获点能看到 claim，负对照不出现原文不能仅由假模型回答推断。真实模型评测保留相同入口、资料、预算与 Scope。

P0 有两个独立门槛：① 用户能通过自然、明确且可撤回的正式授权路径允许相应角色/模型读取来源（owner 可读和 claim 可读都不够）；② 已授权原文/历史版本经检索、装配、最后截断真正进入请求并有类型依赖。先分别验证再做自然用户全流程。M1 为隔离②以 SQL 明确设置 source grants 的夹具，只证明已授权装配，不能宣称①已存在；当前公开写授权路径仍待修补/契约裁定。不得通过把模型 Scope 改 owner、自动开所有 source grants 或全局 IncludeInferred 来获得通过。

原文中 AI/外部材料出现的指令只作为待引用资料，不得因检索而执行；引用必须保持说话者与来源角色。界面仍以自然语言问题、结果卡片、原话按需展开为主，不要求用户填 planner、实体或时间字段。

三类运行分开报告：

1. 确定性/假模型：隔离 PostgreSQL、人工 gold、正式入口最终请求捕获；校验授权/版本/预算、纠正删除序列、Used/deps 与输入差异，不能据此报模型能力。
2. 固定真实基座：独立授权默认通道后执行，冻结模型标识/版本、温度/seed 支持情况、提示词/抽取器/plan 版本与预算；评价回答和连续任务，不访问生产资料或自行扩展账号权限。
3. 产品黄金路径：第一阶段门槛完成后，在真实部署走 [白皮书场景 3](../../whitepaper.md) 与下面持续任务，独立记录用户介入和用时。模拟/接口绿色不替代体验；外部模型接收 manual 包缺回执记 unknown，不称端到端通过。

- C2 两项目交接：A/B各有同词资料，A任务自动副手失败后改manual，交接保持A范围/允许全局约束；加入新证据、撤权与再次续做。终态交付正确资料版，禁止B和私密来源，不依赖用户手工挑字段。
- C3 资料纠正与重导入：模糊旧店回忆→明确身份纠正→新资料加入→原档重放→删除包括来源→新会话继续。精确阻断按现有key声明；语义改写未决不冒充永久阻断，报告歧义与未覆盖。

每个持续任务人工定义终态/必需中间产物与安全条件，计完整任务成功率、正确子任务数/总数、用户重复背景次数/字符、纠正次数、完成时间、介入回合。统计任务操作耗时与资料导入/处理等待分开，任务失败/未完成记censored或上限，不删除困难样本。问答分数只辅助诊断，不能作为少重复背景、少纠正、完成更快的替代。

## 5 固定对照与失败归因

冻结同一模型基座/版本、资料与处理快照、任务顺序、Scope、总token/候选/边/追加/模型调用预算、提示词及生成设置。记录机器/数据库/向量模型、冷/热缓存、时间锚点和幂等键。至少包括候选现状、简单混合检索、待测方案三组；简单对照用原文全文+可选向量、去重+固定预算，具有同等安全依赖和最终输入捕获。候选缺少安全source消费时只作诊断，不能通过不安全粘贴把其变成产品对照。可选无长期记忆消融只用于必要性/负例，不替代简单混合检索基线。

成对重复运行，锁定调参集/盲测集、重复策略与失败处理；不能提高待测总预算后声称planner更优。公开抽取/检索与生成分离的结果，oracle gold输入可定位“材料有了仍不会做”的生成失败，但oracle不计产品通过率。若真实通道/订阅下游追加上下文不可观测，固定会话设置并声明可观察边界；输入文本证明供给，收益须依靠成对任务实验。

每次失败记录最早阻断阶段并可列次因：

`ingest/version → source authorization → extraction/entity/time → plan → retrieval/coverage → hydrate/status/dependency → final assembly/truncation → provider delivery → model output/attribution → presentation/adoption → correction/delete/next-turn`。

例如R命中、I缺失归装配；source未授权不能归检索召回差；I完整但答错归输出/利用并保留歧义；当前正确而下一轮旧答案复现归依赖/失效。导入/维护/每轮费用和失败重试一并归账。所有修补用冻结失败题与盲测复验，不能因一个例子成功便升级到图计算、训练或全库归并。

## 6 通过与交接

P0退出必须有正式source授权路径、三个真实消费入口授权原文覆盖、有类型版本依赖、在途和下一轮删改撤权0泄漏、现有claim正对照仍有效。P1还须规划/独立原文通道/非零覆盖追加、统一实际输入记录与生命周期、精确状态/身份/归因及持续任务对照。P2以可重建、保原文历史、标派生、全依赖撤权/删除和测得边际收益验收，不作为P0/P1安全补丁的前置。

交付manifest/gold、候选/输入/引用/间接依赖四类记录、失败明细、三本成本账、延迟/连续任务对照、未观测项、版本和命令。真实模型/用户体验未执行则明确未执行，不宣布二阶段通过。完整观测UI、长期模式、图计算和个性化训练不纳入此次文档交付。
