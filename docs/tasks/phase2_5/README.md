# 第 2.5 阶段：记忆整理（任务入口）

2026-10-04。依据：[白皮书](../../whitepaper.md) 5.1、5.6–5.8 和第 16 章，[记忆架构](../../memory-architecture.md) 1.2。来龙去脉和实验数字见 [讨论稿](../../research/memory-next-direction.md)。流程规则见 [任务流程规则](../process.md)。

## 1 要交付什么

让记忆从「一条条追加的句子」变成「整理好的现状」，并且在替用户办事时用上它：

- 每条记忆知道自己关于什么（项目、主题、领域、人）、是哪一类（身份、口味、对助手的要求、目标、进展、一次性的事、看法、关于别人）、是不是长期成立。
- 新说法进来时和旧的比：重复的并掉，被替代的退出当前视图。不再有「待确认」清单。
- 有一层现状：交接说明、每个分组一张现状卡、一张期限表。
- 秘书和副手办事时先拿现状，再按强度查细节，重要的事办完自查一遍。

## 3 分几批

每一批单独上线，上线当天有能感受到的变化。前一批在线上验证过，再上下一批。

| 批 | 做什么 | 上线后能感受到 | 状态 |
|---|---|---|---|
| **评测集**（和第 1 批并行） | 一百个以上的办事任务，六类，带标准答案；固定的办事和打分方式；本机真实数据上的跑法和人工抽查表 | 有一个可信的数字，以后每批改动前后各跑一次 | [V2](V2-eval-set.md) 已交 Draft [#184](https://github.com/soaringjerry/PCAS/pull/184)：671 条虚构记忆、120 题、三对照三次测量，见下方记录 |
| **第 1 批：分组和类型** | 每条记忆归到项目、主题、领域，标上类型和是否长期成立；后台分批做、带规则版本、可接着跑；资料库里能按分组翻记忆 | 记忆不再是一长串，能按「PCAS」「租房」「对助手的要求」翻 | 契约和任务包已写：[第 1 批](batch1/README.md) |
| 第 2 批：新旧比较 | 新记忆和同组的旧记忆比，合并重复、标出被替代的；导入的分支对话只整理一次；人名别名合并；可信度按证据自动定，取消「待确认」 | 同一件事不再出现五条；过时的说法不再被秘书引用 | 未写 |
| 第 3 批：现状层 | 现状卡、期限表、交接说明的生成和随记忆更新；一个「关于你」的页面 | 打开就能看到系统对你和每件事的了解，能点回原话 | 未写 |
| 第 4 批：办事时用上 | 秘书和副手的上下文改为四层接力；轻、中、重三档；自查；对助手的要求常驻生效；花费记录里记下档位 | 说一句话不用交代背景；往外发的东西更少出错 | 未写 |

第 2–4 批的契约在前一批上线、评测集有了基线之后再写。

## 4 约束

- 不改白皮书和记忆架构。发现它们和实现冲突时告诉协调者。
- 一个文件只有一个写入者；每个任务一个分支、一个 Draft PR，base 是该批的集成分支。
- 迁移编号由协调者分配。第 1 批用 035。
- 整理是原地补写标签，**不产生新的记忆修订**，不让依赖这条记忆的旧回答变成「依据已更新」。
- 记忆的可见范围不因整理而变窄：整理不写 `scope.project_id`。
- 测试、文档、示例只用虚构内容。真实记忆、线上查询结果和截图不进仓库。
- 部署由协调者做，先备份。
