## 规则与操作序列

历史对话的分段提取优先级为 9，准备与入口为 10，搜索索引、向量和摘要为 20；用户新输入仍优先。对话生成持久分段任务后即收掉冗余消息入口，不写虚假的完成进度。领取任务按持久优先级走索引，遇到整页不可领取时按排序键向后翻页，每次只检查 500 项，不退回全队列计算、排序。租约回收、暂停、先存着、来源版本变动仍生效。

| 操作 | 预期 |
|---|---|
| 导入准备完成 → 旧索引任务早于对话分段 | 先领取对话分段，全文成功后才增加已整理 |
| 600 条消息属于同一对话 → 生成分段任务 | 冗余入口全部收掉；原文和待整理计数保持；首次 AI 调用前进度为零 |
| 生成分段 → 来源修改 → 旧分段执行 | 指纹发现变化，生成新分段，旧模型结果不能提交 |
| 首片成功 → worker 中断 → 继续 | 从未完成片接着处理，不重复首片、不提前计进度 |
| 一页 500 个入口被等待中的对话过滤 → 后面可执行任务 | 能领取后面的任务，不扫描排序全部等待任务 |
| 超过 500 个暂停任务 → 后面的可执行任务 | 能领取后者；暂停项保持等待，恢复后继续 |
| 两个 worker 同时领取、租约过期 | 不重复持有同一任务；过期任务能再次领取 |
| 用户新输入与大量历史提取、索引同时等待 | 新输入先领取 |
| 升级时旧队列已有对话分段 | 保留分段；收掉冗余入口、降低索引优先级，不重传、不重置进度 |

隔离 PostgreSQL 验证这些序列，并保留合成大队列的索引查询计划及耗时；上线核对真实导入进度增长。此次不调整模型并发。
