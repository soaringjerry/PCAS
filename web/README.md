# PCAS Web 原型

用来明确真实使用需求的交互原型（[需求文档](../docs/prd.md) §8）。数据只保存在本机浏览器，
尚未接入后端。[记忆基础服务骨架](../docs/memory-service.md)已建立；页面通过 `src/store` 里的 action 读写数据，后续在这一层接入服务，并按后端领域模型调整映射与异步状态。

## 运行

需要 Node.js 22.12 或更新版本。

```bash
cd web
npm install
npm run dev
```

提交前运行：

```bash
npm run lint
npm run type-check
npm run build
```

## 结构

界面按 [设计原则](../docs/design/principles.md) 做减法：能在后台做的不让你操作，要花钱的 AI 活都放在
按钮上并标出大概花费。

| 路径 | 内容 | 对应需求 |
|---|---|---|
| `/` | 首页，两条线：**紧迫**（有截止，或者有人在等你）和**在推进**（没截止，靠事件往前走）。每行最多一个动作：让副手推进一步，或者查看它做好的结果。拿不准的记录和推测收在“需要你确认”里 | §3、§5 |
| `/t/:id` | 一件事（待办、想法、项目）：说明、子任务或条件、工作记录（副手的结果和文档）、来龙去脉，底部交给副手 | §3、§4 |
| `/library` | 资料库：记忆、来源与后台作业、训练数据 | §2、§3、§6 |
| `/settings` | 后台自动做的范围、副手每天的额度、各 AI 能看到的记忆、导出全部数据 | §5 主动但可控、§6 |

旧的 `/today`、`/inbox`、`/upcoming`、`/ideas` 都跳回首页。

后台自己做的事：

- 把握大的记录直接收下（设置里可以关），拿不准的才问你。
- 想法等的条件满足时自己回到“在推进”，并说明是哪份资料触发的。
- 没截止的事放久了也不提醒，就摆在那里。

在一件事里干活：

- **副手**：点上方的建议（写方案、拆成子任务、起草、总结进度），或者在底部直接说。它带着这件事的背景和
  “带上 N 条记忆”里勾选的记忆开工；没确认的推测默认不带。
- **结果**：出现在工作记录里。按内容采纳：清单加成子任务，总结写回进度，其余存成文档；可以先改再采纳
  （修改记为纠正）。“依据 N 条记忆”能看到副手收到的全部内容。
- **手动交接**：选“手动交接”时不花额度，复制内容给任意 AI，再把回复贴回来。

还没有接后端，副手的输出是按规则生成的示例。

## 快捷键

| 键 | 作用 |
|---|---|
| `⌘K` / `Ctrl K`、`/` | 搜索、新建、跳转，或者让副手推进当前这件事 |
| `↵` | 在底部输入框里发给副手（`Shift ↵` 换行） |

## 走一遍典型场景（§7）

1. 首页底部点“试试导入一份成本测算”：放着的想法「用本地小模型做记忆提取」因条件满足回到“在推进”，并说明原因。
2. 打开它，点“转成待办”；在待办页底部展开“带上 N 条记忆”，把刚导入的成本数据“确认后带上”。
3. 点“写方案”，结果存成文档；再点“拆成子任务”，采纳后加成子任务。
4. 采纳的结果同时成为一条训练候选（资料库 → 训练数据）。

设置页底部“恢复”可以回到初始示例数据。
