# 任务 W1：副手能联网查资料

2026-10-03 用户反馈：让副手调查 yufolo 的公开资料，报告里写「直接访问失败」「站内域名搜索无结果」，没有任何网上查到的内容。由协调者直接修。

## 原因

联网搜索只接在秘书和旧的导办台问答上。交给副手的工作（写方案、起草、查资料、拆步骤、总结）调用模型时没有打开搜索，副手的说明里还写着「只根据所给事项、来源和记忆回答」，所以它只能如实说查不了。

## 改法

- 副手运行改用带搜索的调用（`internal/postgres/runs.go`）。通道支持搜索时（ChatGPT 订阅的 Codex 通道）模型可以自己决定搜不搜；其他通道照旧按给它的资料回答。
- 副手的说明加两段（`deputyInstructions`）：需要公开信息时可以联网查，查到的注明来自网络并写出网址，和来自用户资料的内容分开说；查不到就直说、写明试过什么，不要编。搜索词会离开这台机器：用户明确要查的名称可以搜，资料里别人的姓名、电话、地址、账号、金额和其他私事不能放进搜索词。
- 每次运行实际做过的搜索记在运行记录里（`searches`），以后观测台可以显示。

## 谁能联网（改完之后）

| 角色 | 能不能 | 说明 |
|---|---|---|
| 秘书 | 能 | 原来就能 |
| 旧的导办台问答 | 能 | 原来就能 |
| 副手 | 能 | 这次加的 |
| 后台整理记忆、读图 | 不能 | 有意不开：这些只应该看用户自己的资料 |

通道方面：只有 Codex 通道有搜索。Sign in with ChatGPT 通道和按量计费的接口现在都不带搜索，用这些通道的秘书或副手照旧离线回答。要让它们也能搜，需要按各自的接口另外接，记入待办清单。

## 测试

`internal/postgres/desk_codex_test.go` 的假 Codex：副手运行必须带着搜索打开的配置；后台整理必须不带。这是一条已有测试，原来断言「副手不联网」，按这次的改动改了预期。
