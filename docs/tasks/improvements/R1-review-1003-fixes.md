## 交给执行者（后端规则，四条）

**R-2 生成期间依据被更正，结果不清空。** 现在：副手生成时它引用的资料被更正，模型正常返回后结果被清空、标成失败，但花费已经记了。白皮书 5.5：纠正只标「依据已更新」，不清除。改成：

- 依据被**更正**（内容改了，资料还在、授权没变）：结果保留，状态是做完，标「依据已更新」，**不自动采纳**，由用户决定用不用。
- 依据被**删除**，或这个副手对它的**授权被收回**：结果照旧清空并标失败（删除要传播，不能把已删的内容留在结果里）。花费记录保留。
- 两种情况都要有测试；还要测「一部分被更正、一部分被删除」时按删除处理。

**R-5 副手续写要看到文档现在的样子。** 现在：用户改了副手写的文档再让它继续，新请求里只有上一次运行的输出，没有用户改过的正文；用户自己新建的文档也不带。改成：续写、修改类的请求带上这件事当前的文档正文（按现有的长度上限截取），上一次的输出不再单独带（它已经在文档里，或者被用户改掉了）。

**R-6 秘书调用结束后结算预留的额度。** 现在：按量计费的通道先按最大用量预留，结束后只记实际花费，预留的不释放，当天预算被虚占，后面的对话被拒绝。改成：调用结束（成功、失败、取消）都把这次的预留改成实际花费；失败且没有返回内容时归零。副手运行和后台整理的预留也照这个核对一遍。

**R-7 改期后旧的提醒不再发。** 现在：提醒已经排进待发，之后把截止时间改到明天，旧时间的那条仍然发出去。改成：发送前核对这条通知对应的提醒是否还是当时的时间；对不上就作废不发（首页置顶也不再显示）。结果通知（`run:` 开头）不受影响。

要求：先写出复现它的测试（改之前失败、改之后通过），再改实现；不改已有测试，需要改预期的旧测试列在 PR 说明里；每条说明规则对应的代码位置。
