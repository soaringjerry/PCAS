## 目标

把“我去年说去成都要干什么来着”拆成一个能开发、能验证、能估成本的端到端最小交付。说明可以复用什么、缺哪一段，不另起记忆系统。

## 必须调查

1. 入库 → 分段 → 抽取 → 陈述/实体/经历/证据 → 检索 → 卡片/原文展开的真实调用路径，列文件和关键符号。
2. 哪些表和类型已有但没有自动写入；时间是发生/有效时间还是表达/记录时间；来源版本、权限、纠正、删除怎样影响结果。
3. Secretary、Recall 和副手上下文是否共用检索路径，各自缺什么；指出可共用的最小接口，不让不同调用方各造一个 planner。
4. 项目范围、别名、同名实体、否定、意向/已决定/已完成、晚导入旧资料，以及纠正后重导入的边界。
5. `actions` JSON 收据进入分段/向量/摘要的现状，以及治理入口；原始审计记录仍须保留。
6. 现有 12 条合成资料/7 个来源的回放能证明什么、不能证明什么；当前吞吐、成本和召回率哪些尚无数据。

## 方案应包含

- 一个统一、版本化的查询条件草案：时间轴及范围、主体、人物/地点/实体、陈述性质、工作室范围、预算、歧义与回退；均为待审提案，不直接变更 API。
- 先保存原文、异步提取、结构化定位、向量补漏、核对更正与现状、卡片与原话链接的端到端数据流。
- 最小任务切分：写入抽取、查询规划、检索执行、前端呈现、独立评测；各自文件边界、输入输出、依赖和迁移顺序。
- 状态序列表：相同来源重放、来源升级、晚导入旧消息、用户纠正、撤权、删除、索引未完成、抽取失败/重试、模糊时间、零结构化命中。
- 带干扰项的评测方案：日期记错、同名人/地、只在上文出现地名、间接指代、取消/完成、更正、历史导入、低活跃、受限来源、删除重放、工作室边界。
- 指标分别记录证据召回、错人错事错状态、权限/删除泄漏、覆盖缺口、P50/P95 延迟、上下文实际 token、每条资料处理费用、每次查询费用。阈值先提案并说明基线，不能编造达标数据。
- 这一阶段明确不包含习惯推荐、完整云盘、模型训练和手机持续采集；保留接口空间即可。
