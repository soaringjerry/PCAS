# 任务 L1：资料库的「来源」按出处合并

2026-10-03 用户提出（「资料库里面乱七八糟」）、确认方案。由协调者直接实现。

## 之前的问题

- 每说一句话就是一张卡片，满屏都是「秘书原话 · desk · 1 条」。导入一份两万条的聊天记录会多出两万张卡片，而且每次读取工作区都要把它们全部带上。
- 系统自己写的操作记录（建待办、改待办的流水，`actions`）和修正记录（`corrections`）也被当成来源显示。
- 卡片上露出内部用词 `desk`、`actions`；每张卡都写「已连接」「原文已保存」，没有信息量。

## 规则

**R1 一个出处一张卡。**

| 出处 | 卡片 | 点开 |
|---|---|---|
| 跟秘书说的话（包括没处理完就中断的） | 一张「跟秘书说的话」，写共多少条、最近一次什么时候 | 逐条的列表 |
| 添加记忆时写的话 | 一张「添加记忆时写的话」 | 逐条的列表 |
| 快速记录 | 一张「快速记录」 | 逐条的列表 |
| 从 Telegram 发来的 | 一张「从 Telegram 发来的」 | 逐条的列表 |
| 导入的聊天记录 | 每次导入一张，名字是导入的文件名，写共多少条消息 | 逐条的列表，每条带谁说的、所在对话的标题 |
| 单份资料（上传的文件、粘贴的文字、接入应用推来的） | 每份一张，名字是它的标题 | 直接看原文 |

**R2 不显示的。** 系统的操作记录和修正记录不是资料，不在这里显示。它们没有被删，秘书回答时该用到的依然用得到。

**R3 列表。** 新的在前，一次 50 条，「再看 50 条」接着读。超过 10 条时有一个搜索框，按字面搜这一处里面的文字和标题（`%`、`_` 当普通字符）。点一条看原文，和以前看原文是同一个面板。

**R4 状态。** 正常时不打标签。单份资料还在处理时标「处理中」；任何卡片里有处理失败的，标出来并写一句说明。合在一起的卡片不因为其中某几条还在后台处理就标「处理中」；「先存着」的导入也不标。

**R5 用词。** 不出现 `desk`、`actions` 这类内部用词，不写「已连接」「原文已保存」。

## 数据

- 工作区快照的 `sources` 从「每份资料一行」改成「每个出处一行」：`id`（单份资料是它自己的编号；合并的是 `said`、`memory-input`、`telegram`、`import:<归档编号>`）、`name`、`kind`（`said` / `note` / `telegram` / `import` / `file`）、`single`、`status`、`note`、`itemCount`、`lastSyncAt`。去掉了 `method`。
- 新接口 `GET /v1/workspace/source-groups/{key}/items?q=&cursor=&limit=`，只有主人能调用，返回 `{ items: [{ id, title, excerpt, role, at }], next }`。
- 没有迁移。
