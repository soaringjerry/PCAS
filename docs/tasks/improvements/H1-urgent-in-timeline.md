# 任务 H1：说了「尽快」的事排进首页时间线

> **Historical task record.** This text records an earlier phase or investigation.
> Use the [current documentation](../../README.md) and [project status](../../status.md) for new work.
> Its old assignments, limits, and precedence statements do not govern current development.

2026-10-03 用户提出、确认。背景：用户说「yufolo要尽快开始推广了 不能拖了」，秘书建了待办，但它没有具体时间，首页时间线只显示今天定了时间的事，所以它不出现。用户不要在首页加新的模块，要它出现在时间线里。

**上线后用户能感受到的变化**：说了「尽快」「不能拖」的事，每天都排在首页时间线最前面，时间那一栏写「尽快」，直到做完、取消，或者给它定了时间。

## 规则

**R1 一个标记。** 待办多一个字段 `urgent`（布尔，默认假）。它和待办的其他内容一样存在 `work_items.document` 里，不加列；迁移 030 只负责给已有数据打标记（R7）。工作区快照里着急的待办带 `"urgent": true`，不着急的不带这个字段。

**R2 谁来标。**

- 秘书建待办（`create_task`）和改待办（`update`）的动作多一个可选字段 `urgent`。用户的话里明确表达了着急（例如「尽快」「不能拖」「马上」「赶紧」「抓紧」「越快越好」）时，模型给 `true`；用户说「不急了」「不用赶」时，改待办给 `false`。没提到时不带这个字段，原值不变。提示词里写明这条规则，并写明：只说了一个具体时间不算着急。
- 用户可以在事项页自己开关（R5）。
- 撤销建待办、撤销修改时，`urgent` 跟着回到之前的值。

**R3 什么时候在时间线上显示「尽快」。** 同时满足：`urgent` 为真；状态是待办（没做完、没取消）；没有定时间（没有截止时间，也没有安排时间）。定了时间之后，它按那个时间排进时间线，和普通待办一样，不再显示「尽快」；`urgent` 的值保留，时间被清掉后又回到「尽快」。

**R4 排在哪。** 首页「今天」的时间线里，「尽快」的事排在所有定了时间的事前面，多条时按创建时间从早到晚。时间那一栏显示「尽快」两个字，不显示钟点。手机上最多五行的限制不变，行的先后是：到点了、有人在等、尽快、今天还没到的、今天已经过去的。有「尽快」的事时，不显示「今天没有定了时间的事」那句话。

**R5 事项页。** 待办的事项页在「情况」那一行里：着急的显示「尽快」，点一下带出一句「这件事不急了」；不着急的显示「标成尽快」，点一下带出一句「这件事要尽快」。和这一行其他几项一样，靠说来改，不是开关（2026-10-03 改：原来做成了开关，不符合白皮书「按钮只剩三种」）。只对没做完的待办出现。

**R6 回执。** 秘书建待办时标了着急的，回执文字末尾带「· 尽快」。

**R7 已有的数据。** 迁移 030 把现有的、状态是待办、没有定时间、标题里含「尽快」「不能拖」「不能再拖」「马上」「赶紧」「抓紧」「越快越好」之一的待办标成着急。其他已有数据不动。

## 不做的

- 不在首页加新的模块。
- 记忆（意向、计划）本身不进首页时间线；这里只管待办。
- 不改提醒的时间和方式：「尽快」的事不会因此多发通知。
