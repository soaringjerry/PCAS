# PCAS Web 原型

用来明确真实使用需求的交互原型（[需求文档](../docs/prd.md) §8）。数据只保存在本机浏览器，
还没有接后端；页面只通过 `src/store` 里的 action 读写数据，接后端时替换这一层即可。

## 运行

需要 Node.js 22.12 或更新版本。

```bash
cd web
npm install
npm run dev
```

提交前运行：

```bash
npm run lint
npm run type-check
npm run build
```

## 结构

三栏工作台：左边是视图和项目树，中间是可以同时开多个的标签页，右边是上下文（AI 会看到哪些记忆、
来源、来龙去脉），底部是状态栏（后台作业、AI 是否在工作）。

| 路径 | 内容 | 对应需求 |
|---|---|---|
| `/today` | 今天：需要你拿主意的事（唤醒、AI 结果、出错），以及逾期、今天、正在做、等待中的待办 | §3 TODO 与日程、§5 |
| `/inbox` | 收件：AI 提取的候选和推测，按键收下、调整或不要，可批量 | §5 捕捉轻便 |
| `/upcoming` | 接下来：之后几天的安排和还没排期的待办 | §3 TODO 与日程 |
| `/ideas` | 想法：刚回来的、进行中的、放着的（带再看的条件） | §3 IDEA 追踪与唤醒 |
| `/t/:id` | 一件事的工作页：属性、子任务、文档、AI 工作线程 | §3、§4 |
| `/library` | 资料库：记忆、来源与后台作业、训练数据 | §2、§3、§6 |
| `/settings` | 自动化范围、各 AI 能看到的记忆、导出全部数据 | §5 主动但可控、§6 |

在一件事里干活：

- **AI 工作**：在下方输入指令，或点“写方案”“拆成子任务”“起草”“总结进度”。AI 带着这件事的背景和
  右侧勾选的记忆开工；结果可以存成文档、加成子任务、写回进度，或者先改再采纳（修改记为纠正）。
  选“手动交接”时，复制内容给任意 AI，再把回复贴回来。
- **文档**：每件事挂着自己的 Markdown 文档，AI 起草的也可以继续改。
- **上下文**：右侧列出 AI 会看到的记忆，可以逐条取消；未确认的推测默认不带，确认后才会带上。

还没有接后端，AI 的输出是按规则生成的示例，状态栏会标“演示模式”。

## 快捷键

| 键 | 作用 |
|---|---|
| `⌘K` / `Ctrl K`、`/` | 搜索、新建、跳转，或对当前这件事让 AI 动手 |
| `J` `K`、`↵` | 在列表里移动、打开 |
| `X` | 多选，选中后出现批量操作栏 |
| `C` / `T` / `S` | 完成 / 推到明天 / 切换状态（今天、接下来） |
| `A` / `E` / `⌫` | 收下 / 调整 / 不要（收件） |
| `P` | 转成待办（想法） |
| `⌘\`、`⌘.` | 开关侧栏、上下文 |
| `Alt W`、`Alt [` `]` | 关闭标签、切换标签 |

## 走一遍典型场景（§7）

1. 在“今天”点“导入成本测算”：搁置的想法「用本地小模型做记忆提取」因条件满足被唤醒，并说明原因。
2. 点“转成待办”，打开这件待办；在右侧把刚导入的成本数据“确认后才会带上”。
3. 点“写方案”，结果存成文档；再点“拆成子任务”，一键加成子任务。
4. 采纳的结果写回这件事，并成为一条训练候选（资料库 → 训练数据）。

设置页底部“恢复”可以回到初始示例数据。
