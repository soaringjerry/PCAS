# U2：设置、待确认内容与事项页的日常使用体验

2026-10-01。基线 `59e25da`（stabilization/acceptance-candidate，已含 U1），分支 `stabilization/U2-settings-things-ux`，Draft PR base `stabilization/acceptance-candidate`。执行者 Opus 5.5。没有合并、没有部署。

用户的要求：「把设置界面和任务事项界面变得更符合人性化」「主要是设置里一堆乱七八糟的东西，不知道是干什么的，主要是那些功能开关」「单独一个收下鬼知道是干什么的，收哪里去」。

走查用正式构建产物（`npm run build`），由自己的静态服务在 127.0.0.1:18158（基线）和 18159（改后）提供；所有 `/v1` 请求在浏览器内用合成数据应答，静态服务对 `/v1` 一律返回 500、不转发。没有连接后端、数据库、模型、邮件、Telegram 或任何真实账户。视口：桌面 1440×900、手机 390×844（触屏）。每个开关的真实效果以 S1 的源码核对清单为准，这里没有重新调查后台。

## 改了哪些用户流程

1. **打开设置**：先看到四格当前状态（时间、提醒发到哪、几个模型已配置、今天的 API 预算），再按要做的事分组：时间和地点 → 提醒 → 模型和预算 → 资料 → 数据 → 高级。
2. **拨一个开关**：标题写结果，下面一行「现在：…」随开/关变化；保存中开关不可再点，成功在标题旁显示「已保存」，被拒绝则在同一行显示「没保存上，还是原来的设置」，开关不动。
3. **连接模型、Telegram、其他应用**：密钥、地址、单价、Webhook 这些表单收进一行一行的展开项；收起时也写着状态（已填密钥 / 未连接 / 同步失败 / 这台服务器没开通）。
4. **处理「读到了但拿不准」的内容**（原来叫「收下」，而且在产品里点不到）：设置和资料库都显示条数，资料库里逐条处理，按钮直接写结果：创建待办 / 保存为想法 / 保存为记忆 / 忽略这条。
5. **在事项页改标题和说明**：看得出能改，离开即保存并显示「已保存」；保存被拒时草稿留在框里并标红，可「再存一次」或「改回原来的」；秘书在别处改了标题/说明，页面会跟着变。
6. **在事项页改状态、截止、提醒、项目**：标题下每一项是一个可点的小块，点哪项就在秘书输入框里起哪句话；没定的显示「定个截止时间」「加个提醒」「归到项目」。
7. **用副手的结果**：按钮写去向——加入 N 个子任务 / 创建 N 件待办 / 保存为文档 / 追加到说明 / 更新项目进度；不再有「放回去」「放回来」「看看」。

## 仍有的限制

- 没有在真实账户、真实通知或真机上验证；「已填密钥」「N 个已配置」只反映服务端报告的配置状态。
- 保存失败的具体原因仍只在顶部横幅里（来自 `StoreProvider`，不属于本任务文件）；行内只说没保存上。
- 截止时间、提醒、状态、项目仍然通过秘书改，没有做直接编辑控件：那需要时间换算和命令契约，未在本任务范围内。
- 候选处理不能撤销（后端没有把这些命令列为可撤销）；「忽略」后在界面上没有恢复入口，后端有 `restoreCandidate` 命令。
- 想法页的「再放放」没有改：它只设置 `snoozedUntil`，按 S1 的核对不能在前端承诺一周后一定回来，改名之前需要先定后台语义。
- 副手失败时未知原因仍显示「出了点问题」；「重试 / 重新生成」会再次产生 API 费用而没有事先提示，这是既有行为。
- `domain/lines.ts` 的 `unsure()` 现在没有调用方，文件不属于本任务，未删除。
- 截图里「这台设备」显示「通知权限已关闭」是无头浏览器的真实状态，不是合成的。
