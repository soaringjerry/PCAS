# Dreamscribe D-App 开发者指南: 目标与职责

本文档旨在向 Dreamscribe D-App 的开发者阐明您在 PCAS 生态系统中的关键角色、高级目标和核心职责。

## 您的核心目标

您的核心目标是为用户提供一个无缝的、实时的转录体验，并**确保有价值的信息能够被高质量地沉淀到用户的个人“数据熔炉”中**。

您将通过消费 PCAS 提供的抽象能力来实现这一目标，而无需关心这些能力具体由哪个 D-App 提供。

## 您的双重角色与职责

作为一个“能力消费方”，您扮演着两个至关重要的角色：

### 角色一: 实时交互的驱动者

您的第一个职责是驱动实时交互流程。

1.  **请求能力:** 当用户需要转录时，您需要向 PCAS 请求使用 `capability.streaming.transcribe.v1` 这项能力。
2.  **建立管道:** 您将通过 `InteractStream` RPC 与 PCAS 建立一个高效的、端到端的流式数据管道。
3.  **驱动交互:** 您负责将原始的音频数据流发送到管道中，并从管道中实时接收转录后的文本流，将其立刻呈现给用户。

在这一角色中，您应专注于**速度和流畅的用户体验**。

### 角色二: 知识的提炼与沉淀者 (关键职责)

您的第二个、也是更重要的职责是扮演**“知识提炼器” (Knowledge Distiller)** 的角色。PCAS 的核心价值在于其图引擎能够连接高质量的知识，而**保证数据质量的责任落在您的身上**。

1.  **异步处理:** 您需要在您的 D-App 内部，**异步地**处理从实时管道中接收到的文本流。这绝不能阻塞您的 UI 或实时交互。
2.  **上下文理解:** 您是唯一拥有完整业务上下文的一方。您需要利用这个上下文，去理解哪些零散的文本片段可以被组合成一个**有业务含义的、独立的知识单元**。
    *   一个“知识单元”可以是一个完整的句子、一段完整的对话、一个重要的待办事项、或是一个会议的决定。
3.  **“事件化”知识:** 当您识别出一个知识单元后，您需要将其“事件化”——即，创建一个结构化的、高级别的事件，例如 `pcas.memory.create.v1`。这个事件应该包含丰富的元数据，如发言人、时间戳、来源等。
4.  **提交知识:** 最后，您需要通过 `Publish` RPC，将这个高质量的知识事件提交给 PCAS。PCAS 的核心引擎会自动将其存入图数据库并进行向量化，使其成为用户可检索、可关联的长期记忆。

## 为什么是您来做这件事？

将“知识提炼”的职责交给您，是为了：
*   **保证数据质量:** 避免向 PCAS 的“数据熔炉”中注入大量无意义的、碎片化的“垃圾数据”。
*   **利用业务上下文:** 只有您最清楚用户的意图和场景，能够做出最准确的判断。
*   **保持生态解耦:** 让 PCAS 核心和能力提供方（如 `DreamTrans`）保持通用和职责单一。
