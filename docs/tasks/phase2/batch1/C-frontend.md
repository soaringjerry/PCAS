# 任务 C：依据卡片里的原话、「依据已更新」标记（前端）

执行者 Opus 5.5。分支 `phase2/b1-C-frontend`，工作区 `/root/PCAS-wt/b1-C`，PR base `phase2/batch1`。

先读 [本批总览与契约](README.md) 的第 1、3（R7、R8）、5、7、8 节，以及 [界面与交互原则](../../../design/principles.md)。这是一个小任务：两处界面变化，不新增页面、按钮和设置项。

## 要交付什么

### 1 依据卡片能显示原话

秘书回答下面的依据卡片（`SecretaryCards.tsx` 里的 `Sources`）现在每一条是一条记忆的摘要。后端会开始返回原话条目：

```json
{ "kind": "source", "memoryId": "…", "version": 3, "text": "下周去成都，想吃春熙路那家火锅，顺便见老王",
  "sourceId": "…", "sourceVersion": 3, "at": "2026-09-12T03:10:00Z" }
```

记忆条目带 `"kind": "claim"`；没有 `kind` 的旧条目按记忆处理。

- 原话条目要让人一眼看出「这是我当时说的原话」，和提炼出来的记忆区别开。怎么区分由你定（引号、一个小标签、不同的字重都可以），保持现在卡片的安静风格，不要图标堆砌。
- 点一下打开原文，用现有的 `SourceSheet`，行为和现在带 `sourceId` 的条目一样。
- 摘录可能有 600 个字符，可能以「…」开头或结尾。卡片里要有合理的截断，完整内容点开看。
- 同一张卡片里可能同时有记忆和原话，也可能只有原话。

### 2 回答的「依据已更新」标记

对话里的一轮现在可能带 `outdated: true`，意思是：这条回答当时用到的记忆或原话，后来被改过。回答、卡片、回执都照常显示，只多一个标记。

- 在回答附近加一个不抢眼的提示，文字用「依据已更新」。鼠标悬停或无障碍说明里解释一句：「这条回答用到的资料后来改过，内容可能过时」。
- 不加按钮，不加弹窗，不改变回执上【改】【撤销】的位置和行为。
- 没有 `outdated` 的轮次外观不变。
- 被删除清空的轮次（回答是「（内容已删除）」或「（这条回答依据的记忆已变更）」）不带这个标记，外观不变。

### 3 类型

`web/src/domain/desk.ts`：依据卡片条目加 `kind?: 'claim' | 'source'`，对话轮加 `outdated?: boolean`。

## 约束

- 界面上不出现「来源」「陈述」「版本」「依赖」这类内部说法（交互原则：系统内部的概念不出现在日常界面上）。「原话」「依据」可以用。
- 手机宽度（390px）下不溢出、不遮挡输入框。
- 后端还没合进来时，用模拟数据自己看效果；类型和字段名按总览第 3、5 节，不要自己另起名字。
