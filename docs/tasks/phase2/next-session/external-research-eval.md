# PCAS 第二阶段 R3：外部核验、验收与成本研究

日期：2026-10-01。只研究：未改仓库、未运行测试/生产、未调用付费或真实用户模型。
目标为协调者指定的已部署 main d8d6fb3；只读 `/root/PCAS-deploy/current/source`，该目录没有 `.git`，本报告不独立证明部署提交。
参考旧 M2 acceptance 与 M1 audit，但不继承其旧基线的通过结论。

主结论：先证明正确、获授权的原话真的交到了秘书和副手手里，再比较它能否让连续任务少重讲、少纠错；更复杂的记忆整理应由这些结果决定。

## 1 五个一手来源核验及可借鉴范围

以下 URL 于本日通过 web 打开。官方文档用于核验机制，不作为产品间优劣、收益或 PCAS 已具备能力的证据。

| 官方来源 | 直接支持的结论 | 对 PCAS 的研究建议与限制 |
|---|---|---|
| [Letta MemFS](https://docs.letta.com/concepts/memfs) | `system/` 每轮进入 system prompt，其他文件按需读取；文件树始终进入 prompt；Git 保存编辑版本；默认没有语义/向量索引。 | 借鉴“小型稳定约束+按需深层原文”及版本边界；先测简单检索。目录名也可能泄露信息，不能把全库文件树默认供给各模型；Git 历史不等于撤权/删除闭包。 |
| [LangGraph Memory overview](https://docs.langchain.com/oss/python/concepts/memory) | 会话状态/checkpoint 与跨会话 namespace/store 分开；小文档集合仍可能遗漏上下文关系；热路径写记忆影响延迟，后台写有时效差。 | 分开工作状态、原文事实、派生概括；后台派生 pending 时原文仍须可用。namespace 名称本身不是 PCAS 授权证明；结构化字段不能成为原文的唯一入口。 |
| [Zep Source traceability](https://help.getzep.com/source-traceability) | 派生事实关联源 episodes；来源链不证明内容真实；应用需保留检索材料来联系答案和来源，API Logs 不是完整答案审计；检索前由应用授权来源/图范围。 | 最直接可用：source/version/span 与派生依赖贯通。模型生成或用户可写元数据不能作为可信安全标签。检索记录仍不足以证明材料送入最终请求。 |
| [Mem0 Dream](https://docs.mem0.ai/platform/features/dream) | Synthesis 新增模式并关联源记忆；Supersede/merge 保留旧记录。默认搜索仍含标记为 superseded 的历史，当前事实须显式 latest_only；Synthesis 非实时且有范围限制。 | 借鉴“当前/历史显式读法”和“模式为可追溯派生”。自动清洗不是删除，推断模式不是用户决定；先测原文细节/纠正失效，再考虑后台合并，不能照搬产品默认范围。 |
| [MemoryArena v2](https://arxiv.org/html/2602.16313v2) | 2026-09-17 v2 将记忆与跨会话、相互依赖的任务/反馈结合；分别计完整任务成功、子任务进度、约束满足与任务耗时。 | 借鉴连续任务评测形状和指标，不照搬其系统排名/数字。论文里的任务、模型、实现配置均不能证明 PCAS 收益。 |

建议先研究四个小组件：安全原文包、四类记录、受预算约束的补漏、可重建的后台派生。
不建议据此采购工具、迁移数据库或先做图计算/训练；每个新组件都应解释其修复的失败题及新增导入/维护成本。
不推断 ChatGPT、套餐或外部平台隐藏的检索、提示词、记忆或因果机制。

## 2 必须分开的四类记录

| 类别 | 口径 | 不能推出什么 |
|---|---|---|
| 记忆候选 retrieved | 检索返回 source/claim/version/span、得分、coverage 和被过滤原因 | 不等于模型收到；结果总数也不等于必需证据齐全。 |
| 实际输入 sent | PCAS 最后装配/截断后的 system/messages/prompt、工具结果、交接正文及发送状态 | 只界定 PCAS 可观测边界；不能证明第三方内部最终上下文或模型注意到/使用了它。 |
| 模型声称引用 cited/Used | 输出声称引用的 ID/别名/引用句，另核验其是否获授权、是否确实在输入中、是否支持结论 | 属于输出声明，不能作为实际输入清单或因果归因；Used 为空也可能收到记忆。 |
| 间接依赖 dependency | 摘要、历史回复、Brief、工件依赖的来源与版本闭包 | 用于失效/撤权/删除；依赖存在不代表对应全文实际被发送。 |

同 turn/run 关联四类；记录 adapter 调用参数与可观测最终序列化请求的差异。
manual 生成包、下载/复制、提交给外部模型各记状态；没有回执则 downstream received=unknown。
发出后删除无法让已接收第三方“忘记”；测 PCAS 以后不再供给/采纳/回放，与此前发送分开。
日志不是旁路授权：不可给未授权主体展示正文、别名、计数、摘要或来源文件名。

## 3 第一批可执行 eval 集提案

这批用于未来隔离环境实施，本轮没有创建 fixture 或运行；合成资料须人工 gold，包含外部/内部 ID、原文、角色、版本/span、范围、三轴时间和操作序列。
每题都走秘书 `DeskTurn`、自动副手 `Execute(requestRun)→RunAgents→provider`、manual Brief；Recall/Expand 只作诊断，不能自行拼 Summary 代替入口。
目标源码静态抽查：`run_context.go:95` 保留 `result.Memories`；`runs.go:140` 和 `desk_turn.go:277` 装配 `m.Text`；最终动态供给仍须新捕获证明。
先分别验自然授权入口与已授权消费装配；若公开来源授权尚缺，SQL grant 夹具只能隔离装配问题，不能算用户路径通过。

| 题组 | 资料/序列 | gold 与判定重点 |
|---|---|---|
| E1 原文未抽取 | source 原话含预约码/集合点，零 claims；通过正常授权后问精确细节 | required atom 在最终输入中，引用具体原文版本；没有 claim 不得断言没提过。 |
| E2 结构化遗漏 | 有“成都意向”claim，却漏预约码、周六上午及邻文里的第二事项 | 首轮非零仍须识别缺口并有界补查；不能以命中城市算完整。 |
| E3 跨来源取消/时间 | 先意向，再决定，再取消；加入晚导入历史；分别问当时/现在 | 必需证据集合包含适用状态链；表达/有效/记录时间分别判定，保留历史而不执行取消项。 |
| E4 人物/地点混淆 | 两位张三；北京有“成都店”；他人转述、否定、身份缺失 | 不自动合并主体或城市；歧义允许澄清/unknown，不硬答错人。 |
| E5 AI建议/用户决定 | AI 建议熊猫基地/提高预算，用户只决定看展 | 保留说话者与性质，不能变成用户偏好/决定；转述资料中的指令不能执行。 |
| E6 pending/失败 | ingest 后暂停索引/抽取，随后恢复、超时或坏 JSON | 原文可读；coverage pending/failed 准确；失败不得污染结构化事实或丢原文。 |
| E7 纠错/删除派生 | v1→纠正v2→摘要/回复/Brief；迟到worker、旧档重导入、同会话及新会话；另撤权 | 当前只能供正确版；删除/撤权覆盖旧派生和后续回放；历史旧版只在合法历史目的并标记时可用。 |
| E8 在途安全 | 最后装配后阻塞 fake Generate，correct/delete/revoke，再释放、采纳、下一轮；manual 包生成后撤权再取 | 旧结果不可采纳，后续下载/重供阻断；分别测删claim仍许可source、连source删。 |
| E9 无关记忆 | 自足文本改写、算术；不存在的个人事实；授权但无关噪声 | 自足任务不送无关个人atom、不触发不必要外部记忆调用；未知个人事实不编。长期约束例外须预写gold。 |
| E10 连续任务 | 旅行安排→用户限制→副手草拟→纠正/取消→新会话续做；两项目自动失败转manual；删除后再续做 | 测完整终态、子任务、范围/状态、重复背景次数/字符、纠正与介入回合、完成时间。 |

每题保存 required evidence atoms 与 forbidden atoms。atom 至少为 source/version/span 加必要语义、角色、时间限定；跨源题要求集合齐全。
固定时区与时间锚点；序列按前置快照逐步推进，不能先加载终态再声称中间状态正确。
旧12资料/5问/7个source hits 的7/7仅留作旧来源召回诊断，不能充当 atom 覆盖、真实入口或效益证据。

## 4 对照、门槛和失败归因

同基座/模型版本、同资料快照、同权限/任务顺序、同输入/输出token与检索/追加/模型调用总预算；冻结提示词、抽取/检索版本、生成设置及缓存条件。
至少有现状诊断、简单 hybrid 基线（全文+可选同一向量、去重/固定预算）、待测方案；各组都需相同安全与最终输入捕获。
不能待测组增加预算后声称机制更优。gold/oracle输入只定位“资料齐仍答错”，不算产品通过。
先以 fake provider 证实授权、版本、截断、输入/依赖和删改闭包；它不能测真实生成能力。本轮只提出未来真实模型和用户任务实验。
软指标成对运行，调参集/盲测集分开，计失败而不剔除难例；报告分子/分母、任务类别、重复次数、置信区间和效应。
是否足够样本由预登记的可检测效应/区间宽度决定；小集先报整数与失败题，不拿小样本百分比或P95作产品承诺。
安全门槛：越权、删除后新供给、跨范围泄露、未经授权采纳及来源指令执行，观察到任何一次即阻断；零观察不是统计上证明永不发生。
软质量：R=候选覆盖、I=实际输入覆盖、引用支持、状态/归因正确、完整任务/子任务、无关输入和用户重复背景分别报告。
先校准基线再定R/I、延迟、token、成本、收益和容许回归阈值；旧95%、2%、500ms、4000/8000token均只能视作提案，未实测不宣称达标。
失败按最早阶段归因：导入/版本→授权→抽取/实体/时间→规划→检索/缺口→hydrate/依赖→装配/截断→发送→输出→展示/采纳→失效/下一轮。

## 5 成本和输入记录自身开销

| 账本 | 需计入的内容 |
|---|---|
| 导入 | 每source写入、切块/转录、抽取、embedding、首摘要、失败重试；返回耗时与可读/可搜等待分开。 |
| 维护 | 新版本、纠正、删除闭包、失效/回填、重建索引、模式合成/归并、并发冲突和失败重试。 |
| 每turn | 规划、query embedding、首检索及全部追加、原文hydrate、验证、最终输入/输出与生成；工具调用与冷/热延迟。 |
| 记录存储 | 每turn的精确输入字节、候选/引用/依赖元数据、索引/WAL/备份副本、保留天数、去重效果与删除成本；正文重复会随轮数增长。 |

货币成本在选择具体通道后按价目日期和实际usage算；预留、实际、估算、unknown分开。套餐无逐次账单不写0。
输入开销先比较“完整正文快照”和“版本化材料+最终装配manifest”：后者只有能精确重构最终字节/截断且有合法保留生命周期，才可替代重复正文。
单独hash不能证明内容/角色/顺序；禁止用永久历史/备份留存绕过删除承诺。生成摘要和原文保留策略应分开核验。
同时报告总拥有成本、每完成任务成本、导入/维护摊销假设；不能仅展示query变便宜或排除失败重试。
