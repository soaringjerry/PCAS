# PCAS 界面与交互原则

这几条是讨论后定下的，界面和后台逻辑都按它来。改设计前先对照这里。

## 定位

PCAS 就是干活的地方：一天里任何时候都会打开的超大号秘书加副手。
用户操作越少越好，更多的逻辑在后台跑。

## 界面：功能不少，界面极致简洁

- Apple 式设计：只露出当下需要的东西，其余放到第二层或后台。
- 首页是一个办事大厅（2026-09-30 起，替换原来的两栏首页）：左边「今天」，右边「项目」和「想法」，
  中间一个导办台。三块屏各按自己的规律动：今天按时间，项目按进展，想法安静地流过。
  它们不是同一堆事的不同筛选，所以不算并列视图。
- 导办台是首页唯一的输入框：问句直接回答并给出处，其余的记下来交给后台整理。
  它上方是叫号条（等你拍板的事），下方是「你不在的时候，我做了这些」。
- 只有三样东西会自己动：新回执、「现在」那条线、没人用导办台时慢慢流过的想法；
  鼠标指着、正在输入或系统设置了减少动态效果时都停下。
- 不做侧边栏。项目已经在大厅右边的项目墙上，侧边栏再列一遍只会重复，还把三块屏挤窄。
  顶部只留一条细栏：回大厅（PCAS 标志，不在大厅时后面跟当前页标题）、搜索（`⌘K`）、资料库、设置。
  新建项目、跳到某件事都在命令面板里做。手机上这条栏只剩图标。
- 不做标签页、状态栏和常驻的记忆栏。快捷键提示只出现在顶栏的搜索按钮上，别处不放。
- 系统内部的概念（候选、推测、曝光度、来源、训练样本）不直接出现在日常界面上。

## 两条推进线

事情按性质分两种，共用同一套事项和状态。

| | 紧迫 | 在推进 |
|---|---|---|
| 是什么 | 有截止时间的，或者**别人在等你**的 | 没有截止时间的：长期的事、想法、你在等别人的事 |
| 靠什么推进 | 时间 | 事件：新信息到了、前置事情做完了、副手推进了一步 |
| 排序 | 已过截止 → 今天截止 → 别人在等你（等得越久越靠前）→ 近几天截止 | 刚有新进展、条件已经具备的排在前面 |
| 提醒 | 按时间提醒 | **不主动提醒**。放在界面上，有新进展时才排到前面 |

- "你在等别人"放在"在推进"。对方回复了就带回来；到了约定的跟进时间还没动静，才转进"紧迫"。
- 很久没动的事安静地待着，不会消失。

## 后台做什么，按钮做什么

- **后台自动做**（便宜，用规则或小模型）：提取和归类、更新状态、识别"别人在等你"、检查条件和唤醒想法、去重。
  拿不准的才问用户，归进首页叫号条里的「拿不准的」。
- **按钮触发**（花 token）：写方案、查资料、起草、拆步骤。这些按钮只在事项页里出现，首页不放；
  按钮上写预计花费，设置里有每日额度。副手做完放进叫号条等你看，不会自己往外发东西。
- 往外发送、删除、花大钱之前一定先问。
