# P2 秘书一轮对话的数据库耗时

2026-10-05；基线 `origin/main` 的 `4401e73`；分支 `fix/p2-turn-speed`。

## 结果

同一构造方法的虚构库：30,000 条原话、20 个事项、5 个已采纳结果，分别加 2,500 / 10,000 条记忆。所有内容为虚构人物云杉、霜叶的盆栽与季度汇报资料。使用立即返回的 HTTP 假模型，实际执行秘书入队、准入、生成前后校验、写回和完整快照；初始化、造数据与 ANALYZE 不计入对话时间。

| 记忆数 | 原实现数据库合计 | 完成后数据库合计 | 完成后整轮墙钟时间 |
|---|---:|---:|---:|
| 2,500 | 49.193 秒 | **1.319 秒** | 1.323 秒 |
| 10,000 | 177.182 秒 | **1.856 秒** | 1.862 秒 |

完成后两档各测三轮，表中取整轮数据库合计的中位数，增长 **1.407 倍**。10,000 条的三轮分别是 **1.975、1.638、1.856 秒**，全部低于 2 秒；2,500 条分别是 1.502、1.319、1.150 秒。原实现 2,500 条也取三轮中位数；10,000 条只测一轮，原有两分钟生成超时不足以完成，为测完整基线仅在冻结的测试副本中延长为十五分钟。生产超时未改。

## 每一步的收益与语义证明

以下为依次添加改动后的单轮结果；最后一行换成三轮中位数。相邻样本有缓存与运行抖动，不能把整轮差值全部归因于某一条查询。

| 改动 | 2,500 合计，秒 | 10,000 合计，秒 | 10,000 档相邻整轮减少 |
|---|---:|---:|---:|
| 原实现 | 49.193 | 177.182 | — |
| 036：来源键增加 `(owner_id,claim_id)` 索引 | 45.745 | 70.629 | 106.553 秒 |
| 回忆：当前版本只计算一次，以 JOIN 连接 | 4.998 | 12.946 | 57.683 秒 |
| 事项：只计算该事项实际依赖的当前版本 | 3.313 | 7.701 | 5.245 秒 |
| 原话权限：只查对应证据目标的当前版本 | 1.956 | 4.201 | 3.500 秒 |
| 秘书：召回后只读命中 ID 的记忆 | 1.618 | 3.306 | 0.895 秒 |
| 快照：同一行集只统计一次 | 1.465 | 2.828 | 0.478 秒 |
| 036：最新卡片的有序部分索引 | 1.319 | 1.856 | 0.972 秒 |

- **来源键索引**：旧主键从 `source_id` 开始，不能限定通过 `claim_id` 做的来源有效性检查；单条查找原计划扫其余来源键，重复调用放大成本。索引不改查询、版本解析或写入维护规则。`TestP2IndexDoesNotChangeBytes` 在同一只读事务中，通过另一连接建索引，比较建前建后的原实现完整快照与当前记忆 JSON。
- **回忆的单语句 CTE**：保持原 `applicable_claim_versions` 及其两个时间参数，显式 materialize 一次，再 JOIN；history 模式跳过未使用的计算。10,000 档回忆由 58.189 降至 0.768 秒。只加 CTE、JOIN 和替换当前版本相等条件，原范围、候选、打分、排序、片段和分页不变。不是持久物化表或跨查询缓存。计划里 CTE 的 10,000 行仅计算一次，以 Hash Left Join 接入候选。
- **事项依赖**：仍以原函数计算版本，只把输入限制为这个事项的所有已采纳结果的实际 run_dependencies。80 次调用保留，生成前后校验保留；该类别由 4.773 降至 0.043 秒。原有授权、排除、来源状态、主体类型、推断与项目条件未改。测试比较事项正文和依赖 JSON，并覆盖撤权、排除、来源撤回及纠正。
- **原话权限**：将原函数的全用户 JOIN 改成每个证据目标的有界 LATERAL 查找，`OFFSET 0` 保持按目标查的计划。原话仍受所有当前有效证据目标的权限和排除项约束，未放宽任何 NOT EXISTS 条件；窗口类别从 2.084 降至 0.067 秒，其余来源依赖校验也受益。测试直接比较每份原话的可见性，并在随机变更后比较权限、事项正文、召回。
- **秘书按 ID 读取**：原秘书先读全部当前记忆，然后只用召回命中的条目。现在沿用原读取函数、授权和过滤，只增加命中 ID 条件；旧 AnswerDesk 完整读取路径保留。10,000 档列表类别由 1.817 降至 0.939 秒。测试比较原/新实际提示词、送入模型的记忆、依赖，以及全量读取后筛选与按 ID 查询的 JSON，包含万条档。空 ID 集合显式返回空集。
- **合并统计**：原记忆总数与整理统计使用同一可见行集；额外 JOIN 的 claims 父记录由 claim_revisions 外键保证存在。复用 Organize.Total 填 MemoryTotal，减少两条查询，字段与数字不变。完整快照逐字节对比覆盖权限和源状态变化。
- **最新卡片索引**：对 active 记录按 `(owner_id,updated_at DESC,id)` 建部分索引，保持原卡片排序与 LIMIT。10,000 档列表类别从 0.988 降至约 0.037 秒；实际计划只访问 201 行而非排序整库。2,500 档仍可能选择不同计划，所以其类别耗时约 0.24 秒，整体比值仍满足要求。索引前后同一事务对比完整快照与全部记忆。

没有存储新的“当前版本”物化数据，因此没有需要补维护的写入路径。迁移 036 只建两个索引。整理逻辑 `organize.go`、已有测试预期、接口和响应形状均未改；秘书的开始及结束完整快照均保留。

## 对原因判断的验证

1. **按行求当前版本确实有成本，但不是简单的条数翻倍、时间翻倍。** 来源键缺索引导致每次来源有效性检查扫描更多数据；回忆和原话权限的 JOIN 计划又重复用户级版本解析，增长可超过线性。只加来源键索引就让 10,000 档从 177.182 降至 70.629 秒，而回忆仍达 58.189 秒；还必须改变执行计划。
2. **全部读取后只用二十条的判断成立。** 将读取移到召回后，以实际命中 ID 限定，保留原读取规则和模型提示词内容。
3. **完整快照确实重复统计。** 此外发现生成开始前也读一次完整快照，整轮不止响应里的那一次。本次保留两次完整快照，优化其统计与最新卡片读取即可达标。
4. **同一事项反复校验的判断成立。** 测得一轮 80 次权限检查；本次保留每次检查，只把当前版本计算缩小到实际依赖，不在调用之间缓存旧权限。

计数和召回仍需对相关行集做工作，并非所有查询都变成常数时间；本次达到了任务指定的两档合计及增长比例验收。

## 比对测试及运行方法

`p2_legacy_queries_test.go` 冻结 `4401e73` 的旧查询与读取路径，仅用于比对和可选旧版测时。新旧在同一 REPEATABLE READ、READ ONLY 事务中读同一份数据，序列化 JSON 后按字节比较。快照在生产使用 FOR SHARE，PostgreSQL 的只读事务不允许该锁，测试包装器对新旧仅移除同一条 owner 读取锁；生产锁未改。虚构记忆设置 pinned，避免 Exposure 随两个读调用的墙钟间隔变化；没有放宽字段比较。

- `TestP2QueriesAreByteIdentical`：完整快照、事项正文与依赖、36 组召回、模型提示词与送入记忆；重复验证授权撤回、来源撤回、未来生效、过期、排除、实际纠正写入。召回涵盖 owner / 普通主体 / team、remember / history / continue、空查询、无命中、工作对象。
- `TestP2IndexDoesNotChangeBytes`：建两个索引前后的原读取结果。
- `TestP2RecallTemporalAndVectorBytes`：历史 KnownAt、未来 ValidAt、纠正版本、向量排名及分页。
- `TestP2RandomVisibilityAndSourceSequence`：固定种子 20261005，80 步授权变更、来源撤回/恢复、来源版本升级、AI/用户来源变更、生效时间、事项排除和推断状态；每步比较实际优化的 ID 读取、原话权限、事项正文/依赖及召回。
- `TestP2LargeResultsAreByteIdentical`：10,000 记忆 / 30,000 原话档的完整快照、命中 ID 读取与召回逐字节比对，单独按开关运行。

只对自行创建的 `pgvector/pgvector:0.8.2-pg16-bookworm` 一次性 PostgreSQL 容器设置 `PCAS_TEST_DATABASE_URL`；每个测试还创建并删除自己的 schema。这里未连接线上数据库或容器。模型 HTTP 固定返回：
