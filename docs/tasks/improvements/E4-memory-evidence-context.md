2026-10-03 记忆摘要中的人物、对象和原因可能依赖原对话，使用时需要沿证据补读上下文。用户要求统一优化并补充文档；本文及公开测试仅使用虚构示例。

## 操作序列与契约

| 操作 | 预期 |
|---|---|
| 打开旧记忆 → 点来源 → 看当时对话 | 引用消息突出显示，同一会话当前分支的相邻原话按时间排列，保留用户/AI身份；引用原件仍可完整打开 |
| 普通资料或用户纠正来源 → 展开原文 | 保留原件展开和处理状态；仅在有会话归属时从记忆来源切换到对话阅读 |
| 连续展开更早/更晚 → 重复展开 | 每页有界，游标属于同一会话，无重复，无跨会话拼接 |
| 原话包含「那位同事」「这件事」 | 已有记忆显示需结合上下文核对；不把模糊称呼建立为确定的人名，不合并不同人的实体 |
| 新提取遇到指代 → 上文有唯一明确对象 | 独立陈述补足对象和必要限定；名字必须有原文依据，原话证据仍逐字引用用户消息 |
| 新提取遇到指代 → 对象仍不明 | 保留不明确的状态，禁止编姓名或身份；引用上下文辅助使用 |
| 秘书/副手/手动交办召回旧记忆 | 优先补读依赖指代的记忆的证据上下文，明确对应哪条记忆；AI回复只能用于理解，不当用户事实 |
| 上下文超预算或没有会话归属 | 提示范围有限/不可用，不根据摘要补猜；普通资料继续保留原件入口 |
| 证据/邻近消息被删除或权限关闭 → 再读 | 不返回已删除正文；模型上下文遵守资料可见性及事项排除，受限窗口整体不进入模型 |
| 模型读取后原话变化/撤权 → 提交回答或交办结果 | 上下文原话版本进入依赖账本，沿已有校验和删除传播使结果失效 |
| 不同旧分支、另一会话或另一用户有相同称呼 | 不拼接、不用称呼做跨对话实体合并 |

此改动为读取和提取规则修复，不重写用户已确认的记忆，不批量重跑导入，不新增模型调用。旧记忆通过读取证据上下文立即受益；模糊称呼提示是阅读提示，不代表已经由人工或模型确认对象。新增提取提示要求独立陈述保留必要语境。

## 实现与验证

原文及会话归属来自 `source_versions` / `source_contexts`，证据来自 `evidence`。页面提供分页会话窗口；模型按已召回记忆的证据定位邻近消息，保留角色、时间、版本依赖及预算缺失提示。无会话归属的资料只保留原件，不拼接其他来源。历史旁支只显示引用消息，避免混合多个旧分支。

验证按线上 `memory.NewService(store)` 服务组合启动 API，覆盖接口转发和鉴权/输入边界；另包括分页/重放、跨用户与跨会话、同时间排序、旧分支、删除/撤权、超过预算、模糊实体、旧记忆模型输入和版本依赖，以及手机/桌面来源界面。测试由本次实现者编写，不声称独立测试作者验收。上线按任务流程使用默认订阅通道完成问题、安排、修改与撤销，并清理验收数据。
