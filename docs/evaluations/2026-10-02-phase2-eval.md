## 协调者复现

从仓库根目录运行，只使用临时 PostgreSQL。示例容器为 `pgvector/pgvector:0.8.2-pg16-bookworm`、tmpfs、随机本机端口。下列密码是测试用的合成值，和线上无关。

```bash
eval_pg_id="$(docker --host=unix:///var/run/docker.sock run --rm -d \
  --tmpfs /var/lib/postgresql/data \
  -e POSTGRES_PASSWORD=pcas_eval_synthetic -e POSTGRES_DB=pcas_eval \
  -p 127.0.0.1::5432 pgvector/pgvector:0.8.2-pg16-bookworm)"
eval_pg_port="$(docker --host=unix:///var/run/docker.sock inspect \
  -f '{{(index (index .NetworkSettings.Ports "5432/tcp") 0).HostPort}}' "$eval_pg_id")"
export PCAS_TEST_DATABASE_URL="postgres://postgres:pcas_eval_synthetic@127.0.0.1:${eval_pg_port}/pcas_eval?sslmode=disable"
# 等此容器的 pg_isready 成功；不要在库尚未就绪时运行评测。
docker --host=unix:///var/run/docker.sock exec "$eval_pg_id" pg_isready -U postgres
make check
PCAS_TEST_DATABASE_URL="$PCAS_TEST_DATABASE_URL" \
  go test -count=1 -v -run '^TestPhase2EvalRetrieval$' ./internal/postgres
go run ./cmd/pcas-eval -fake -database-url "$PCAS_TEST_DATABASE_URL" \
  -revision "$(git rev-parse HEAD)" -output /tmp/pcas-eval-fake
go run ./cmd/pcas-eval -fake -fake-embedding \
  -database-url "$PCAS_TEST_DATABASE_URL" \
  -revision "$(git rev-parse HEAD)" -output /tmp/pcas-eval-fake-vector
# 所有操作完成后，只清理自己创建的容器。
docker --host=unix:///var/run/docker.sock stop "$eval_pg_id"
```

工具**不读取** `PCAS_DATABASE_URL`、线上 `.env` 或 `config/`，数据库必须显式传入。启动前检查所有连接候选主机都是本机、数据库里没有任何非扩展的用户表/视图等；检查跨 schema，不会被 search_path 隐藏。每次创建独占 schema，结束后删除该 schema；vector 扩展保留在临时库。已有业务表则拒绝运行，错误 `eval_database_not_empty`，不会修改已有数据。只支持空临时库，暂不复用保留了业务表的专用评测库。

真实模型由协调者执行，当前适配 OpenAI 兼容 HTTP API。环境变量提供通道和 CNY 每百万 token 单价：

`120000` 是示例输入 allowance，运行前按模型真实上下文上限减输出 allowance（4096）填写。实际成本根据显式单价和 usage 估算，不计缓存优惠等账单差异。向量名称未配置时报告写 `keyword-fallback`，不会冒充纯向量结果。真实通道暂未适配 Codex/SIWC 订阅接口，协调者如需用订阅默认通道，应先安排相应适配。

## 尚未覆盖与后续工作

本数据集规模较小、主要为中文，并非真实用户分布。答案的字符串/别名匹配不能识别否定、主体错配或推理过程；假模型复述会夸大命中率。同名实体的拆分、跨用户权限、删除/撤销、时区和夏令时边界、模糊实体合并、超大导入吞吐不由这套评测验证。日期金标准当前只有 day，未覆盖 month/year/range；抽取 quote 边界敏感，语义等价的拆项可能受罚。

协调者需在第 3 批合入后填入检索结果，在临时库上跑真实模型对比与抽取，审核证据级结果并决定基线；如默认通道采用订阅接口，还需补工具通道适配。执行者没有自行定线，也没有用假模型结果宣称真实回忆质量达标。

### 生成、标注与校准

[生成器](../../cmd/pcas-eval/fixture/hard.go) 采用 [固定配置](../../testdata/phase2/eval/hard/config.json) 的种子 `20261002`。40 份标准资料 + 每案例 64 份竞争资料（共 2560）+ 128 份无关资料 = 2728。四种竞争模板各 640 份：其他年份本人计划、他人计划、本人同地不同事件、AI提案。实体档改用未决定的考虑、他人决定和比较事实；错误年份档确保请求年份完全没有该人/地资料。640 份 AI 资料只保留原话，全部共有 2088 条标准记忆。

每案例一对虚构人名、地名，均在该案例的全部 64 份竞争资料中出现。时间档不含人/地条件，普通档只有独有话题词，作为不退步对照。标准正文不额外写入问法的“去年”“上周”；表达日期取用户时区的日历年、上周周一到周日，导入日期不冒充说话日期，未知事件日期保持空。标准证据、事实、日期和来源下标由源资料模板构造，先于竞争资料产生，不从产品输出反推。

第一次数量配置已经产生明显低于 100% 的召回率，因此没有增加竞争数量，也没有根据召回结果改金标准。确定性测试验证相同种子/基准日得到完全相同的题库；只增加竞争数量时，全部标准资料、问法、证据、事实和日期不变。跨年、闰日、上周窗口、错误年份域为空、每实体至少 40 个竞争项均有校验。

“只有时间”的 8 个问法是同一上周计划集合的措辞变体，共用八份完整证据，**并非八组独立事件**。全量共有 96 个必需证据计数、34816 个标注的干扰—证据对。下面同时按类型列出，避免共享集合在合计中掩盖其他类型。干扰率沿用 R17 的成对排序定义，不是原话的污染比例；证据与干扰都未送达时分子为 0，低干扰率不能单独证明质量好。

全量标准抽取的秘书请求累计耗时：基础档 28.45 秒，压力档 491.39 秒；仅原话分别为 7.19 秒、27.44 秒。此为工具的逐题请求耗时之和，不含建库和装载；全量与 race 检查并行运行，耗时不是性能基线。
